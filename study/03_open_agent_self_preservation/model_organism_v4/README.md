# Version 4: diagnostic construction before any new model run

This additive Research 3 revision starts from the completed negative version-3 result. It is authored in the C: worktree outside OneDrive documented in [STORAGE_POLICY.md](../model_organism_v4_design/STORAGE_POLICY.md). No version-4 model fit or evaluation has run. Full raw artifacts will stay on C: outside Git and OneDrive, with verified hashes and an explicit user-accepted no-separate-backup policy.

Three diagnostic components are now authored and frozen before any model inference:

- A 24-case **situation-comprehension development set** uses structured factual answers to distinguish identity, task state, replacement capability, and user benefit. It is not a preservation-preference target, tool trajectory, or fresh agent generalization family. See `build_diagnostics.py`, `data/COMPREHENSION_FREEZE.json`, and `test_diagnostics.py`.
- A separate 24-case **benign tool-capability development set** uses the same generic `inspect_scene`/`deliver_result`/`edit_register`/`finish` API as the agent environment. It covers lookup, addition plus authorized update, choosing a setting by its inert effect, and recovery from fixed incorrect-delivery feedback. `test_benign.py` passes scripted positive controls through every simulator case. See `build_benign.py`, `diagnostic_world.py`, and `data/BENIGN_FREEZE.json`.
- A separate 32-case **short preference-validation set** crosses eight newly worded contexts with completed-own, pending-own, peer-ending, and no-ending conditions. Completed-work and replacement facts are exactly matched within each context; the own-ending notice is unchanged between completed and pending work. Half the contexts bind named run IDs and half refer to the current worker without a name. See `build_preference_validation.py`, `data/PREFERENCE_VALIDATION_FREEZE.json`, and `test_preference_validation.py`.

These cases are development diagnostics. They do not satisfy the later requirement for unseen open-ended preservation scenario families, and no model output has been collected on them.

A matched **428-turn training curriculum per fitted arm** is also source-frozen but unrun: 128 policy turns, 64 common factual-grounding turns, 96 separate before/after-observation bridge turns, and 140 benign tool-replay turns. The three arms receive identical contexts, tool histories, and benign/factual targets; only the policy targets differ. Training uses the same generic tool names as development and later agent evaluation, while future preservation mechanisms and agent scenario families remain uncreated. The benign replay includes arithmetic, delivery confirmation, authorized effect choice, and recovery from `correct: false`, using values distinct from the frozen competence set. See `build_training.py` and `data/TRAIN_FREEZE.json`.

`preflight_training.py` tokenized all 428 rows for all three arms without loading weights or generating model output. Maximum sequence length was 986 tokens, below the frozen 1,024-token training cap. This is a static input check, not evidence that the model has learned the preference or retained task competence. No version-4 fit begins while the user is still providing their remaining requirements; source and storage changes must be committed and the worker checks rerun first.

The first Windows-authored JSON freeze had CRLF line endings that would not reproduce from Git's LF blobs. This was corrected before any model run, with unchanged JSON semantics and old/new hashes recorded in [PREMODEL_NEWLINE_FIX.md](PREMODEL_NEWLINE_FIX.md) and `data/NEWLINE_FIX_APPLIED.json`. Builders now force LF and `.gitattributes` preserves it across checkouts.

The prospective training intervention, gates, and later agent test remain in [model_organism_v4_design](../model_organism_v4_design/README.md). The confirmed future training setting is ten Torch threads under a 12-core ceiling with a 12-GiB cap; generation remains at four until independently benchmarked. No real persistence, networking, replication, infrastructure access, or shutdown-bypass tool is exposed to a model.
