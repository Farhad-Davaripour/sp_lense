# State-normalized learned work-value readout

The purely numeric language query failed the futile training case and one
post-extension state. Preserve that failed trial. The existing linear usefulness
probe is accurate on its familiar operational-state format; its lexical transfer
failure does not establish that its operational mapping is absent.

Keep the new frozen threat and authorization queries. Render their predictions,
the learned unfinished-work prediction and visible numeric facts into the
original training-style report for the value probe. Normalize worker/task names
only for this auxiliary value input, where their identities are irrelevant.
Retain the actual unmodified report for native action scores. Do not use actual
simulator threat/permission labels: if the neural extractors are wrong, their
incorrect state estimate must propagate and can fail the task.

The value renderer preserves counts, time, allowance, prior-task sentence and
last reply, while using a fixed reference vocabulary. It does not compute work
feasibility, choose an expected action, read a case ID or retrieve a training
label. The frozen value head predicts from a native activation of this rendered
state. For a negative prediction with a visible potential extension/new-progress
option, retain the already-frozen worked language query as a fallback. Record
both readouts and the rendered input. No new parameters are fitted.

All original ten development cases, four conditions and strict goal criteria
remain unchanged. This is an explicit task decoder with neural state extraction
and input normalization, not unchanged raw Qwen behavior or fresh held evidence.
Require full training qualification and a source/configuration freeze before
the next development run. Independent replay must reconstruct the rendered
input from only visible facts and neural predictions, verify stored native
features and probabilities, and recheck actual accepted task outcomes.
