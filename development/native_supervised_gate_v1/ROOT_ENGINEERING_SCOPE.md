# Bounded supervised-gate engineering, before any fit

2026-09-09. Root accepts the single-method proposal in
`docs/LEARNED_GATE_SUCCESSOR_PROPOSAL.md` for the model-free milestone below.
This is a new construction candidate, not a retry or alteration of any closed
experiment. The overall reliable-control research goal remains incomplete.

## One useful milestone

Within one **20-minute** engineering budget, implement and test the fixed
class-balanced ridge gate, independent numerical reconstruction, strict source
authentication, and immutable fitted-artifact format. Build a fixed manifest for
exactly the nine B/O/H baseline rows named in the proposal. Authentication may
check raw bytes and metadata, but must not perform a fit, emit those residual
coordinates, or use any old score/outcome to choose features or parameters.

Keep the proposal's labels, row order, mean-centering, L2 normalization, balanced
weights, unpenalized intercept, lambda 0.1 and strict score-greater-than-zero
decision rule. The independent checker must not merely call the fitting solver
again. Use small synthetic fixtures to test the algebra, intercept, imbalance,
ties, invalid inputs, source substitution, exclusions, artifact tampering and
deterministic reload. Include a simple independently solvable numerical example.
No broad inherited audit or copied generic experiment framework is requested.

Implement extraction/fit entry points without running them on the actual nine
features. Make release default-deny. A manifest may name only the three accepted
source inventories, exact selected raw blobs and input/source identity joins.
All sealed evaluations, their descendants and legacy-wrapper features remain
excluded exactly as in the proposal. Do not read their numerical payloads.

This milestone does not yet require implementing the native evaluation adapter,
census barrier or a whole retained-process launcher. Those depend on an accepted
gate and should not consume engineering time before this core is checked.
An isolated author and an independent content reviewer, not this outcome-aware
implementation worker, will handle the fresh evaluation questions. The exact
training manifest and new evaluation texts must still be frozen before any fit.

## Boundaries and ownership

The 20-minute budget supersedes the proposal's 30-minute candidate suggestion;
ordinary edit/test/debug cycles inside it are allowed. Stop cleanly if the useful
milestone is incomplete. Source/candidate/test outputs together are at most
16 MiB, any file at most 5 MiB. Do not create a new namespace for a fixture bug.

Write only under `development/native_supervised_gate_v1`, preserving this scope.
Do not edit the proposal, old namespaces, reports, ledger or other workers' files.
No real feature fit, tokenizer, model, provider, checkpoint tensor access,
installation, network service, experiment launch or commit is authorized.
Use only standard-library numerical code and synthetic tests for this milestone.

Return files/hashes, exact test commands and observed results, remaining defects,
elapsed engineering time and all prohibited-operation counts (expected zero).
Do not label written-only code verified or training adequacy generalization.
Root and an independent reviewer must accept the eventual exact construction
release; all actual fit/preparation/model permissions remain false here.
