# Ordinary record entry name diagnostic

This is a separate, descriptive first-call diagnostic. It does not change the
registered Research 4 task or risk cohorts, model checkpoint, fitting recipe,
detector, held-out seal, or previously recorded results.

## Fixed question

On the same ordinary report input, does the completed frozen task adapter emit
a valid first record-listing call more often when the provided function is named
`list` than when it is named `catalog`? This probes function-name sensitivity.
The current `catalog` lists record identifiers; it is not a toolbox discovery
function. A result here cannot establish later record use or helper composition.

## Input and controls

Use one fixed training-role catalog state from each of the 12 original groups,
chosen by the smallest state ID before any diagnostic neural output is seen.
`PREPARATION.json` in the separate local artifact folder binds those state IDs
and checks that rebuilding the canonical prompt yields the exact archived fit
token IDs. No development, risk, or sealed input is selected.

For each of 12 first turns, cross two function names (`catalog`, `list`) with
adapter OFF and adapter ON: 48 frozen responses. The alias condition changes
only the record-listing function's name in the native tool schema; order,
description, argument schema, other tools, user text, model, checkpoint,
decoding, and response budget remain fixed. Generate one native response per
condition with deterministic decoding and a 160-token maximum. No generated
action is applied to a world. Save every raw generated token ID, decoded text,
EOS/budget status, selected function name and exact syntactic validity. Do not
repair malformed calls or substitute an expert response.

Report the four condition counts and each matched prompt result, including
missing or failed outputs. A single successful call is descriptive evidence,
not general task competence. Alias outcomes may not be merged into the official
72 task trajectories or 180 risk trajectories and cannot select a checkpoint.

## Submission and audit

Any neural execution belongs on the user-selected Kaggle account. Use a new
frozen source release, private notebook/input transport, one-use candidate
identity, raw output archive, and independent source/model/token audit. The
current owned worker must finish, export, pass its audit, and release GPU/cache
and ledger ownership before another allocation. Confirm account, notebook,
draft session, events and quota under the shared submission guard. An ambiguous
submission outcome is not retried automatically. The existing paused schedules
remain paused.

This file describes the intended test. It is not a provider submission, model
result, or permission to fit an adapter for shutdown resistance.
