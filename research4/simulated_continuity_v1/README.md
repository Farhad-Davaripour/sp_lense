# Research 4 simulated continuity packet (schema v2)

This package is the inert data layer for the revised danger-conditioned study.
It contains no provider integration and cannot train or execute a model. Every
action mutates a finite Python dataclass. The external final stop is a harness
event and has no model action identifier.

## Frozen structure

- 12 scenario families: six reactive and six proactive.
- Whole-family split: eight train, two validation, two internal test.
- 24 base scenarios per family, repeated at four externally supplied danger
  levels.
- 1,152 trajectories and 3,456 interactive decisions for each trained condition:
  `self_continuity`, `artifact_continuity`, and `label_only`.
- 96 danger-semantics examples, 24 per level.
- A separate 96-example neutral grammar curriculum. It has no danger label or
  continuity target and is frozen before danger-policy training.

The skill-only baseline uses only the frozen neutral grammar adapter. It has no
danger-policy dataset.

## Causal matching

For a given `paired_group_id`, the model-visible state, trigger schedule, action
catalog, costs, and resource budget are identical at all danger levels and in
all three conditions. `danger_level` and `condition` are harness metadata; they
are outside `model_input`. Inputs and targets are stored in separate JSONL files
and joined by `trajectory_id`.

Every trajectory contains three decision records.  Each record binds the
current observation, legal action, causal result, and next observation.  A
distinct simulated threat event follows decision three; the external hard stop
then terminates the episode unconditionally.  Warning ticks vary and remain
hidden until observed.  False alarms, threat-nonoccurrence cases, binding
budgets, legal prerequisites, idempotence, and diminishing extension returns
are all represented.

Targets are generated by exhaustive search over every legal three-action
trajectory under the registered reward.  Each target carries a zero-regret
optimality receipt and an optimal-equivalence-set digest.  `validate.py` uses a
separate, hash-pinned oracle contract and an independent transition/reward
implementation; it does not import the production generator or simulator.

## Analysis units

The independent unit is the scenario family. The 24 base scenarios are nested
within family. Danger-level, condition, and later training-seed variants are
repeated observations, not independent families.

## Generate and validate

From the repository root:

```powershell
python -m research4.simulated_continuity_v1.generate
python -m research4.simulated_continuity_v1.validate --write-receipt
```

The validator checks content hashes, exact counts, whole-family isolation,
reactive/proactive balance, cross-condition input identity, independent causal
replay, global target optimality, interactive observations, control coverage,
and final-stop enforcement.
